Revised diagnosis: Your capture-phase submit listener (true third arg) IS firing. The Pardot inline script in the same page proves this — it hooks into the same submit event successfully. The sole reason zero requests reach your server is that sendBeacon with a Blob({ type: 'application/json' }) silently fails cross-origin. application/json triggers a CORS preflight, and sendBeacon can't handle preflights properly (it sends with credentials: 'include' which is incompatible with your server's Access-Control-Allow-Origin: *).
What changed in the footer code (replace the entire <!-- Camp Experts Lead Routing --> block):

Primary send method is now fetch() with keepalive: true and proper Content-Type: application/json. This works because fetch handles CORS preflights correctly.
Fallback is sendBeacon with a plain string (no Blob). When you pass a string directly to sendBeacon, the browser sends it as text/plain;charset=UTF-8, which is CORS-safelisted. No preflight, no failure.
Added MutationObserver on .w-form-done as a backup mechanism. If the submit event ever gets swallowed (future library changes, etc.), this catches successful submissions by watching Webflow toggle the success div.
Dedup logic prevents double-sends when both the submit listener and MutationObserver fire for the same submission.

What changed in index.js (three targeted patches):

CORS config now allows campexperts.com explicitly with credentials: true instead of wildcard *.
Added express.text({ type: 'text/plain' }) middleware so the sendBeacon fallback path works.
Both webhook handlers now check if req.body is a string and parse it as JSON if so.

Deployment order: Deploy index.js to Replit first (server needs to accept the new content types before the client starts sending them), then update the Webflow footer code.
